# ADR-001：v5 路线图取代 v4 的 P 编号主线

- 日期：2026-11-03
- 状态：已接受（accepted）
- 决策者：站长
- 背景文档：`ROADMAP.md`（v4，2026-11-01）、`docs/PLATFORM-STRATEGY-2026-11.md`（v5）

## 决策

自 2026-11-03 起，项目主线以 v5（PLATFORM-STRATEGY-2026-11，四条轨道：信任 / 现场 / 分发 / 平台）为准；`ROADMAP.md` 的 P0–P7 编号不再描述主线顺序。v4 文档保留为执行基线，其中的已完成项证据（质量门、动线验收、契约）继续有效。

## 推翻了什么

- v4「先稳定化 → 再完整闭环 → P7 才考虑分发」的顺序。**被推翻的理由**：没有获客就没有反馈，没有反馈就没有产品判断；分发不能排在最后。
- v4 的 P 编号含义。v5 里 P3=分享获客、P4=预订实体，与 v4 的 P3（脱敏分享）/P4（行中执行）**完全不同**——这是 2026-11-03 复核审计发现的实际混淆源，任何引用 P 编号的地方必须注明版本。
- v4「按城市全量覆盖补数据」的资源分配。**被推翻的理由**：单人产能下全量永远补不完，且大部分点位没人去；改为「莫斯科 Top 60 决策就绪」+ 工程周与内容周 1:1。

## 保留不变

- v4 已交付的部分全部保留：Trip v2 编辑器、可行性引擎、交通矩阵、行中执行（M1）、事实账本、41+ 道质量门。
- 「实时多人协作不做」在 v4 与 v5 中一致（v5 只做异步 guest 链接）。
- 质量红线：UGC 只当线索、verified 必须 official、坐标调整人工裁决。

## 废止/影响

- `ROADMAP.md` 顶部已加取代声明；新增引用一律用 v5 轨道名（信任/现场/分发/平台）+ v4 P 编号时注明「v4」。
- 后续每个主线级变更各留一页 ADR（`docs/decisions/ADR-NNN-*.md`），必须回答：推翻了什么、为什么、废止哪段旧文。

## 备注

本 ADR 本身是审计 B8（两份路线图并存且互相冲突）的修复件；审计复核报告见站外 `travel-research/AUDIT-2026-11-03-REVIEW.md`。
