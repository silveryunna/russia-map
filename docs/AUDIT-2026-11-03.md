## 4. 最具创造性的后续方向

评选标准沿用 v5 四条（新颖 / 护城 / 可行 / 可验证），但**只保留"能直接兑现现有资产"的方向**——不再新建领域模型。

### 4.1 旗舰 A：Fact Watch · 事实失效雷达

**一句话**：把 231 条事实账本变成"会自己报警的资产"——官方页面快照 diff → 你行程里哪条事实这周变了。

**为什么是它**：
- 现有 `data/facts/` 已带 `source/reviewAfter/status`，只缺"上次看到的原文哈希"这一个字段。
- 它把"人工核验"（旗舰 A 的证据链编译器）从**一次性劳动**变成**持续监控**，护城河随城市数线性增长。
- 竞品抄 UI 一周，抄"每周比对的官方页面快照历史"要一年。

**最小实现（2–3 周）**：
```text
tools/fact-watch.mjs     抓取 facts 里 official 的 URL → 归一化正文 → sha256
                         与 data/facts/snapshots/{pointId}.json 比对 → 产出 changes.json
data/facts/snapshots/    只存哈希 + 关键片段（不存整页，避免版权与体积）
行程页横幅               「你的行程有 3 条事实本周发生变化」→ 逐条「接受/忽略/去核实」
check-facts 扩展         snapshot 必须与 facts 的 source.url 一一对应
```
**验收**：连续 4 周跑出 ≥1 条真实变更；变更卡片点开能看到"旧值 → 新值 + 官方链接 + 抓取日期"。

### 4.2 旗舰 B：单文件离线胶囊（`.trip.html`）

**一句话**：一次导出得到一个**双击就能用的文件**，发给同行者，飞行模式走完一天。

**为什么是它**：PWA 安装有摩擦（尤其 iOS），微信群传文件才是中国人的真实分发方式。现有 `trip/offline.js` 已经有全部数据，只缺一个渲染器。

**最小实现（2 周）**：
```text
src/pages/trip/capsule.js   纯函数：Trip + points + facts → 单个 HTML 字符串
                            内联：当天卡片 / 时间轴 SVG / 核验清单 / 应急卡 / 地图缩略 SVG
                            交互：只用 <details> + 锚点，零 JS 也能读
导出入口                    today.html 与 plan.html 各加一个「导出行程胶囊」
体积目标                    单天 < 300 KB，7 天 < 1.2 MB（照片不放）
```
**关键拒绝**：不做在线分享链接（要有后端与隐私成本），先做"文件"。

### 4.3 旗舰 C：Trip Lint · 行程体检

**一句话**：把 40 道 CI 纪律产品化——用户拖入行程，输出一份能截图传播的体检报告。

**为什么是它**：这是本项目把"工程优势"转成"用户可感知价值"的**最短路径**，而且天然是分享物（"我的行程体检 78 分，2 个硬冲突"）。它复用 `feasibility`、`facts`、`soft`、`transit-matrix`，几乎零新逻辑。

**检查项（全部已有能力）**：
```text
硬冲突      闭馆 / 最后入场 / 预订重叠 / 跨日 / 超收工线        ← evaluateDay()
证据缺口    unknown 开放时间 / 过期事实 / 无官方来源              ← evidence
时间风险    估算段占比 / 折返次数 / 连续活动时长                  ← soft + transit
一致性      时区错位（N4）/ 离线包过期 / 备份超过 7 天未导出      ← 新增 3 条规则
```
**输出**：`体检报告.md` + 一页可截图的 HTML 卡（红/黄/绿三段 + 3 条最高影响建议）。
**验收**：站长自己的 3 份行程跑出与人工判断一致的 Top 3 问题；报告能被非技术朋友看懂。
