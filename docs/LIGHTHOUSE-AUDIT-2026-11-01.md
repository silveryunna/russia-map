## 2. 端口处置清单

### 2.1 IPv4（来源 0.0.0.0/0）

| 端口 | 备注 | 建议 | 说明 |
|---|---|---|---|
| 22 TCP | Linux SSH 登录 | **限源** | 改为仅放行你的固定出口 IP；或保留但强制密钥登录 + fail2ban |
| 80 TCP | HTTP | 保留 | 仅做 301 跳 443 即可 |
| 443 TCP | HTTPS 站点 | 保留 | 主入口 |
| 3389 TCP **+ UDP** | Windows 远程桌面 | **删除（两条）** | Linux 实例永不适用，纯暴露面 |
| 7000 TCP | frp 隧道 | **改架构** | frps 应只监听 `127.0.0.1`，外网经 SSH 隧道访问；删公网规则 |
| 33670 TCP | LightClaw ACE WebUI | **改架构** | 无鉴权直接暴露；改回环 + nginx 反代 + Basic Auth 或 IP 白名单 |
| 18789 TCP | **无备注** | **先查后删** | 黑箱端口，必须确认监听进程后再处置 |
| ICMP ALL | Ping | 可选保留 | 会暴露主机存活，介意可关 |

### 2.2 IPv6（来源 ::/0）

当前规则与 IPv4 一一对应（22 / 80 / 443 / 3389 TCP / 3389 UDP / ICMPv6），**未做任何单独收敛**。
IPv6 地址无 NAT 遮蔽、全球直接可达，等于把 IPv4 侧的收敛成果归零。建议：

- 至少让 22 与 3389 的 IPv6 规则与 IPv4 保持一致处理；
- 若站点不走 IPv6，可直接不放通 80/443 的 IPv6；
- 用防火墙模板把这套规则固化，新机一键套用。

**现状问题**：整机快照只有一个且是 2 个月前的；SQLite（投稿、AI 台账、账号会话）与上传照片位于 webroot 之外（`/www/wwwroot/julyyunna-art-data/`），既不在 git 也不在任何自动备份里。

建议三层：

1. **秒级回滚**：`update-russia-map.sh` 在 `git reset` 前把当前 webroot 打成 tar，保留最近 N=10 份到 `/root/rollback/`。坏提交上线后一条命令即可还原，不必等 CI。
2. **每日数据备份**：SQLite（`sqlite3 .backup` 而非 copy，避免 WAL 半写状态）+ uploads 目录，打成加密 tar 保留 14 天。密钥放 webroot 之外。
3. **每周整机快照**：保留最近 2 份；重大变更前手动补一份。当前策略改为"每周自动 + 保留 2"，不再依赖 8 月那一份。

## 6. 资源利用率：从"静态托管"升级为"常驻服务层"

核心判断：4C4G 常驻、300GB 流量、40GB 盘，目前只跑 nginx + php-fpm + frps。**常驻算力、定时调度、出网 IP、快照镜像四项能力全部闲置。**

按 ROI 排序的四个设想：

### A. 事实哨兵（最贴合项目痛点）
- 定时 worker 每晚扫 `data/facts/{city}.json` 中 `reviewAfter` 到期的条目，抓官方来源做 diff；
- 有变化 → 生成"事实修订提案"入库并推送（保留原值、建议值、证据、审核历史）；
- 抓不到 → 保持 `unknown`，**绝不填成估算**（与项目既有哲学一致）；
- 服务器有固定出网 IP 和常驻时钟，比开发机可靠；2GIS 配额可借服务端排队 + 缓存摊薄。
- 对应风险：ROADMAP §15「单人运营燃尽」。

### B. 瓦片烘焙（最贴北极星指标）
- 按路线（动线 buffer 2km、zoom 12–16）服务端批量预取瓦片，输出静态目录 + manifest；
- 前端"下载这条线的离线地图"，SW 拦截 tile 请求走本地；
- 服务端代抓一次、N 个客户端复用 —— 这是 300GB 流量与 40GB 盘的正确用法；
- 直接支撑"飞行模式核心任务成功率 ≥95%"。
- **前置**：瓦片供应商的使用条款是否允许服务端缓存与离线分发，需先确认。

### C. 胶囊托管
- POST 编译好的脱敏单文件胶囊 → 返回 `julyyunna.art/c/<短码>`；
- 同行者扫码打开即自包含（内嵌 SVG 地图 + 行程 + 核验清单 + 应急预案），打开一次即可离线；
- TTL + 访问码 + 定期清理；只存加密 blob。

### D. 心跳守护 + 自动快照
- 见第 3、4 节。

### 次要但高性价比
- 3 Mbps 是硬瓶颈：brotli、瓦片长缓存 + 文件名带版本、大包夜间 cron 预生成避开白天峰值；
- 把 AI 幻觉过滤与硬约束校验挪到服务端 Node，前端不再需要信任 AI 输出（对应 ROADMAP 的"AI 幻觉 = 0"指标）。
